# HU-01. Consultar mi tablero

**Como usuario, quiero ver mis tareas organizadas por estado al abrir la aplicación, para conocer mis pendientes sin buscar en notas o mensajes separados.**

## Diagrama de casos de uso

Esta historia está representada en el [diagrama general de casos de uso](Historias-de-Usuario.md#diagrama-de-casos-de-uso).

## Explicación del caso de uso

Al abrir la aplicación, el usuario accede directamente al tablero, sin iniciar sesión ni introducir credenciales. Mientras se recuperan las tareas, el sistema indica que la carga está en curso.

Cuando la consulta termina correctamente, el sistema muestra las columnas **Pendiente**, **En curso** y **Completadas**. Cada tarea aparece una sola vez, en la columna de su estado guardado, con su título visible. La consulta no modifica las tareas.

Si no hay tareas, se muestran las tres columnas vacías. Si falla la lectura, se comunica el error sin presentarlo como un tablero vacío. Una columna sin tareas permanece visible aunque las demás contengan información.

La creación de la primera tarea corresponde a [HU-02. Registrar un pendiente](HU-02.%20Registrar%20un%20pendiente.md), ya integrada en el tablero. HU-01 mantiene la responsabilidad de consulta.

## Criterios de aceptación

| ID | Dado | Cuando | Entonces |
| --- | --- | --- | --- |
| CA-01 | Que abro la aplicación. | Termina la carga correctamente. | Accedo directamente al tablero, sin iniciar sesión ni introducir credenciales. |
| CA-02 | Que hay tareas guardadas. | Consulto el tablero. | Veo sus títulos en Pendiente, En curso o Completadas según su estado; cada tarea aparece en una sola columna. |
| CA-03 | Que todavía no tengo tareas. | La consulta termina correctamente. | Veo las tres columnas vacías y puedo registrar la primera tarea mediante HU-02. |
| CA-04 | Que falla la lectura de los datos. | Se comunica el resultado. | Recibo un mensaje de error y el fallo no se presenta como un tablero vacío. |
| CA-05 | Que la consulta sigue pendiente. | Espero su resultado. | Puedo identificar que las tareas están cargando. |
| CA-06 | Que hay tareas guardadas y se conservan los datos locales. | Recargo o vuelvo a abrir la aplicación en el mismo navegador y sitio y la lectura termina correctamente. | Veo las tareas con sus títulos y estados guardados. |

### Verificación de esta entrega

- `npm run lint`, `npm run typecheck` y `npm run build` comprueban código, tipos y compilación.
- `npm test` ejecuta las 20 pruebas automatizadas de lectura descritas a continuación. La suite está incluida en el repositorio y llama a la función real `leerTareas()` con localStorage simulado.
- Se inspeccionó el tablero vacío en el navegador integrado a 1280 × 800 y 390 × 844: tres columnas, contador 0/10 y ausencia de desbordamiento horizontal. En móvil las columnas se apilan verticalmente. No se observaron errores ni advertencias de consola durante esa revisión.
- La carga está presente en el HTML inicial del servidor y la lectura comienza después de la hidratación. Las comprobaciones con tareas y fallos se hicieron sobre la función de lectura; su recorrido visual completo en navegador queda pendiente de una prueba de integración.

Estas comprobaciones no acreditan la matriz completa de navegadores ni el objetivo de 3 segundos con Wi-Fi y 4G, ni suponen la aprobación del MVP.

### Pruebas automatizadas de lectura

La suite está en [tests/leer-tareas.test.mjs](../../tests/leer-tareas.test.mjs). Desde la raíz del repositorio, después de instalar las dependencias con `npm ci`:

```bash
npm test
```

Se utiliza el ejecutor de Node.js, sin un framework adicional. Para funcionar con Node.js 20, TypeScript transpila los dos módulos reales de tareas a una carpeta temporal fuera del repositorio. Las pruebas utilizan esos módulos, simulan las respuestas de localStorage y restauran el entorno al terminar. No necesitan servidor, credenciales ni datos reales del navegador.

En las lecturas con acceso al almacenamiento se comprueba que se consulta una vez por llamada la clave `control-de-actividades:tareas`. Después de cada caso se comprueba que no hubo accesos a operaciones distintas de `getItem`, asignaciones ni eliminaciones, aunque la función capture un error. La simulación no verifica el comportamiento del almacenamiento de un navegador real.

**Resultado observado:** `npm test` terminó con 20 pruebas aprobadas, 0 fallidas y 0 omitidas.
