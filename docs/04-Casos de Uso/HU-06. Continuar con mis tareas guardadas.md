# HU-06. Continuar con mis tareas guardadas

**Como usuario, quiero recuperar mis tareas y sus estados al volver a abrir la aplicación, para continuar organizándome sin anotarlas otra vez.**

## Diagrama de casos de uso

Esta historia está representada en el [diagrama general de casos de uso](Historias-de-Usuario.md#diagrama-de-casos-de-uso).

## Explicación del caso de uso

Después de crear tareas o guardar cambios de estado, el usuario puede recargar la página o volver a abrir la aplicación dentro de la misma etapa de almacenamiento. El sistema recupera la información guardada y muestra las tareas en **Pendiente**, **En curso** y **Completadas**, conservando sus títulos, estados y fechas de finalización. La consulta del tablero se describe en [HU-01. Consultar mi tablero](HU-01.%20Consultar%20mi%20tablero.md).

Durante el desarrollo, el sistema guarda y recupera las tareas desde la base de datos de **Supabase**. En esa etapa, el autor es la única persona con acceso al sistema y no se incorpora un inicio de sesión a la aplicación.

Al terminar el desarrollo, la versión final guarda y recupera **todas las tareas desde localStorage**, incluidas las completadas. Los datos quedan asociados al mismo navegador y sitio y se recuperan siempre que se conserven sus datos locales. La versión final no utiliza Supabase para persistir o sincronizar el tablero y no comparte tareas entre navegadores o dispositivos.

El cambio de Supabase a localStorage corresponde a una etapa del proyecto. Al iniciar esa etapa, las tareas existentes en Supabase no se conservan ni se trasladan al almacenamiento local. La versión final comienza sin tareas procedentes del desarrollo. Completar una tarea no cambia el almacenamiento utilizado.

Mientras se recuperan las tareas, el sistema indica que la carga está en curso. Si la lectura falla, comunica el error sin presentar el fallo como un tablero vacío. Si el almacenamiento rechaza una escritura, comunica el fallo y no confirma que el cambio se guardó correctamente.

Los cambios guardados deben mantener el máximo de **10 tareas en curso**, el cierre definitivo de las completadas y la consistencia entre estado y fecha de finalización, también ante operaciones desde dos pestañas. Esas reglas se detallan en [HU-04](HU-04.%20Limitar%20mi%20trabajo%20en%20curso.md) y [HU-05](HU-05.%20Completar%20una%20tarea.md).

Las condiciones de disponibilidad y recuperación ante pérdida de datos se definirán al comenzar la implementación de localStorage. Esa definición queda pendiente para esa etapa y no bloquea el desarrollo con Supabase. Esta historia no establece una política de respaldo ni una garantía de recuperación si se borran los datos locales.

## Criterios de aceptación

| ID | Dado | Cuando | Entonces |
| --- | --- | --- | --- |
| CA-01 | Que creé tareas y guardé cambios de estado. | Recargo la página o vuelvo a abrir la aplicación dentro de la misma etapa de almacenamiento. | Recupero las tareas con sus títulos, estados y fechas de finalización guardados. |
| CA-02 | Que estoy en la fase de desarrollo. | Guardo un cambio y vuelvo a consultar las tareas. | Se utiliza Supabase para guardar y recuperar los datos. En esa fase, solo el autor tiene acceso al sistema, sin incorporar un inicio de sesión a la aplicación. |
| CA-03 | Que utilizo la versión final y se conservan sus datos locales. | Guardo y vuelvo a abrir el tablero en el mismo navegador y sitio. | Recupero desde localStorage todas las tareas con sus títulos, estados y fechas de finalización. |
| CA-04 | Que se realiza el cambio de Supabase a localStorage al finalizar el desarrollo. | Se inicia esa etapa. | Las tareas de Supabase no se conservan ni se trasladan al almacenamiento local. |
| CA-05 | Que el almacenamiento de la etapa no está disponible o rechaza una escritura. | Intento guardar un cambio. | Se comunica el fallo y no se confirma un guardado exitoso. |
| CA-06 | Que falla la lectura de los datos guardados. | Abro o recargo el tablero. | Recibo un mensaje de error y el fallo no se presenta como si no hubiera tareas. |
